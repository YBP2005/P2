## 摘要（草稿）

目标检测研究报告的数字，通常来自一个被当作"留出集"的划分。我们审计了这个前提，**审计的是配置**——
而 2026 年的两篇已发表工作审计的是**图像**（训练图的近重复出现在测试集里，见 §2.1）。**两者机制不同，
且本文测出的偏差方向不是单一的——按语料而异（§5.1）。**

在**我们自己**的实验语料中，**14 个语料有 6 个**的 YOLO 配置把 `val:` 与 `test:` 指向同一目录
（→ `yamls/MANIFEST.md` 及全树扫描，§4.1）；其中 SHWD 的**三个键全部指向同一目录**
（→ `A_results_20260915/root/shwd_data_b.yaml`）。这不是"污染"——训练与评测在图像层面不重叠——
而是**用被报告的划分来选 checkpoint**。我们量化了它：在 569 个已发布 run 上，
"最佳 epoch 减末轮"的**选择溢价**在**四个受检格上符号一致为正**，且**基线臂获益更多**
（配对差 +0.416 / +0.526 / +0.272 / +0.449 pp，四条 95% CI 均不含 0）
（→ `selection_premium_local_20260916.txt`、§5.1 第一级）。
在**他人发表的**训练日志上（**20 条**完整日志 / **6 个来源**，全部溯源到内容哈希）同一成分同样普遍存在：
中位数 **+1.04 pp**、最大 **+5.65 pp**、**18/20** 为正（§5.5）。
在三分划语料上做**配对差分**后，val 与 test 上的臂间差**偏移方向按语料而异**：
两个头条格显示 val **低估**效应（p = 0.0053 / 0.0263），
两个已注册的复制对显示 val **高估**（p = 0.0173 / 0.0182），其余九格不显著。
在**公开检测基准**上，我们逐行审计 19 个基准并引入三种计数单位；
**通用 YOLO 分发包中两键字面同路径：2/19 ≈ 11%**（PASCAL VOC、SFCHD）；
**实际报告的数来自非独立划分：12/19 ≈ 63%**（其中 4 行证据不足）
（→ `split_units_19rows_20260916.md`）。最后我们给出一条可复算的补救协议（三分划），
并在其上报告：把选点集与报告集分离后，效应**复现**（n = 10，smoke→SFCHD **+1.434 pp**，
置换 p = 0.0020 = n = 10 下界，10/10 种子为正；
**该读数首报于伴生论文**（the budgeted fine-tuning study；本文记作 **P1**），本文引用），
但**更多种子把均值拉低了 9%–29%**——
这是选择膨胀的直接测量（→ `r10_initvar_and_seedext_20260915.md` §1.1）。
在**同一个三分划协议**上补做 **2×2 评估**（41 个 run、**164 次评估、0 失败**，`best`/`last` × `val`/`test`）后得到本节最硬的一条数：
**在 `val` 上选点得到的增益，在独立 `test` 上只兑现 19%**（`prem_val` **+0.883 pp** → `prem_test` **+0.172 pp**），
且五个臂格中有**两格的兑现为负**；同一批复算还与归档 `sio_b_results.csv` 在 41 个 run 上**最大差 0.0047 pp**（§8.6）。

**定位（一句话）**：我们不主张"首次审计检测基准的划分问题"——该体裁在 CV 顶会已有位置
（CVPR 2026《Data Leakage Detection and De-duplication in Large Scale Geospatial Image Datasets》），
**图像级近重复的审计也已被两篇 2026 年工作完成并量化**。本篇占的是三者之外的一格：
**配置级别名 + 偏差方向按语料而异（四格符号一致、两格在 val 上反向）+ 报数须先声明单位。**

## 1. 问题

YOLO 生态的默认工作流是：把数据划成 `train` / `val` / `test` 三个键，训练时按 `val` 上的指标
保存"最佳"权重，然后**把该权重的 `val` 指标写进论文**。当 `val` 与 `test` 指向同一目录时，
这两步作用于同一批图像：**选点集与报告集是同一个集合**。

这**不是数据污染**。我们核对了图像层面的交集：训练与评测不重叠，交集为 0（→ 骨架 §1 声明 A）。
问题在**测量**：报告的端点是"在被报告的那个划分上选出来的"，因此它是一个**选择过的值**，
而不是留出估计。

**这个失败模式在工程上已被承认，但在文献里没有被测成量。** 两个可引用的证据：

1. **`roboflow/rf-detr` PR #1329**（已 merged）的代码是
   `split = "test" if self.train_config.dataset_file == "roboflow" else "val"`。
   原文："So for `dataset_file="yolo"`, **`evaluate(split="test")` silently returns val metrics**.
   The held-out test split is unreachable and **nothing warns**."
   其修法是"**没有 test 划分就回退 val，但改为告警**"——正是本文分类里的 F-B。
2. **`ultralytics` #25650** 修的是"**KITTI Eigen 的 3 个 test drive 混进了 train**"。

**注意这两条都是工程修补，不是测量。** 而 2026 年的两篇工作测的是**图像级**重复
（训练图出现在测试集里），与本文的**配置级**别名机制不同——差异见 §2.1。

本文问三件事：
1. 这个失败模式在**我们自己的**语料里有多普遍？它的**方向与幅度**是什么？
2. 在**公开基准**里有多普遍？（需要先解决"怎么数"这个问题，见 §3）
3. 有没有一条**可复算**的补救协议，补救之后结论是否还成立？

**为什么这是选择问题，而不只是泄漏问题**：我们量到的偏差正是模型选择文献讲了几十年的那一条——**用验证集上的分数挑模型，会让上报分数偏乐观**（Cawley & Talbot, JMLR 11(70):2079–2107, 2010；Varma & Simon, BMC Bioinformatics 7:91, 2006），经典解法是把选择**嵌进**评估里（嵌套交叉验证），而不是去重数据。在检测基准里，这条解法**要先读配置才用得上**：选择这一步是隐式的——训练脚本按 fitness 写出 `best.pt`，论文上报的就是它——所以只信划分名字的读者，看到的是"留出集评估"，而管线实际做的是**取最大值**。因此，另外两条直面基准退化的文献线（测试集复用：Recht et al., PMLR 97:5389–5400, 2019；"标准划分"并非中立：Gorman & Bedrick, ACL 2019: 2786–2791）所描述的偏差，本条配置路径**不需要复用任何数据、也不需要错误划分**就能达到。
我们把前者作为一般陈述，报告检测领域的具体实例：**选择溢价（best − last）及其向独立划分的转移**（§5、§8）。

**读法**：上面这些工作**没有一篇做错**——**它们审的是图像，我们审的是配置**。
图像级重复让指标**虚高**（两篇都测了这一点）；配置级别名让**臂间比较**发生偏移，
而本文测出这个偏移的方向**不是单一的**：按语料而异（§5.1 第二级）。

**最关键的一条对比**：*Drones* 2026 **也报了 val 与 test 的差**，但结论是 "**no systematic direction**"——
它把两个划分的一致当作"模型选择没有过拟合验证集"的证据。
**本文测的是同一个直觉的不同量，且分成两级报，两级的强度不同**：
① 选择溢价（best − last）**在四个受检格上符号一致为正**，且**基线臂获益更多**
（配对差 +0.416 / +0.526 / +0.272 / +0.449 pp，四条 CI 均不含 0）——**这一级是有方向的**；
② 但在三分划语料上做配对差分 Δgap 时，**符号按语料而异**（2 格 val 低估、2 格 val 高估、9 格不显著）。
因此本文与 *Drones* 的 "no systematic direction" **不是同一句话**：*Drones* 报的是 raw val−test gap
（该量含两划分的难度差，**不可识别**），我们报的是**配对后仍存在的偏移**，
并明确写"**方向依语料而定，不能写成普遍低估**"（§5.1）。
这是两篇都未覆盖的一格，也是本文最主要的可对比差异。

> **顺带值得引用的一条**：*Technologies* 2026 引了 Barz & Denzler 的工作——
> 训练/测试间的近重复图像抬高 CIFAR-10/100 的报告准确率，**清除重复后错误率上升约 9–14%**。
> 这是"图像级泄漏有幅度"的早期锚点，本文应引用。

## 3. 单位：本文的方法学前提

**这是全文最容易被审稿人问穿的地方，因此前置。**

同一个问题"这个基准是不是把 `val` 当成了报告集"，在四个不同的**单位**上有四个不同的答案：

| 单位 | 定义 | 归属对象 |
|---|---|---|
| **release** | 基准**自身发布**的划分产物/脚本是否提供独立留出 test | 发布方 |
| **protocol** | 官方 README/论文/网站声明的划分，且该 test 是否**本地可自评** | 发布方 |
| **yolo_dist** | **通用 YOLO 分发包**（如 Ultralytics 目录）中 `val:`/`test:` 的写法 | 第三方分发包 |
| **reported** | 文献里报告的**那个数字**来自哪个划分、该划分是否独立于选点 | 使用者 |

**本文的立场：任何百分比都必须声明单位。** 我们不给出"唯一的"数字，
而是给出每个单位下**可由逐行标记机械重算**的数（§5）。

**证据类别**同样标注：**官方发布物 / 官方协议 / mirror / generator / 无**。
审计原文自己把这三类失败模式分开（F-A 两键同路径、F-B 无 `test:` 键、F-C `train`/`val` 重叠），
我们沿用，并额外记录**证据来自哪一类**——因为"基准有问题"与"某个第三方 fork 有问题"是不同的主张。
（→ `benchmark_split_audit.md` A:21–28）

## 5. 发现二：选择溢价的方向与幅度

**证据**：`eval_validity/selection_premium_local_20260916.txt`（读**本地归档**的 569 个已发布 run；

**定义**：premium = 单个 run 内 **best-epoch − final-epoch** 的 mAP50-95。

### 5.1 方向：分两级报，第二级的符号按语料而异

本文的方向结论**必须分两级**，两级强度不同。**不能把两级压成一句"普遍低估"**——
这正是外部核对（§5.4）**(II)** 的结论（不是 (I)：(I) 是质疑被推翻，(II) 才是改掉本稿措辞的那条）。

**第二级：在同一批三分划语料上做配对差分 Δgap，符号按语料而异。**

raw 的 `M_val(ê) − M_test(ê)` **不可识别**：它同时含**两划分的难度差**与**选择乐观**两个分量，
实测跨度 **−33.0 ~ +21.2 pp**，而本地归档**没有逐 epoch 的 test 评测**，两个分量无法分离。
可做的是**配对差分**——两臂各算一次 gap，再同种子相减，难度差被消掉：

Δgap =（臂间差 on val）−（臂间差 on test）；**Δgap > 0 表示 val 低估了策略臂的效应**

| p_vistod15 | 10 | **−3.315** | 6.5×10⁻⁹ | [−3.676, −2.953] | val **高估** |
| 其余 9 格 | 3–10 | −2.46 ~ +13.66 | ≥ 0.054 | 均含 0 | **不显著** |

**故摘要原样保留、其弱形式被加强**："val 在两格低估、在两格高估"不再依赖两行 n = 3。两件实施层面的事实与这些数字同行：
40 个 run 的训练**与**评测都在同一台机器、同一套栈上完成（十种子的格从不跨机器）；**我们自己把 `best.pt` 在 `test`

"被选中 checkpoint 的 test 评测"（§7.3 已披露的缺陷），也使 n = 3 → n = 10 的比较是**同口径**的。

**对"兑现率"本身的、由理论驱动的检验（新增）**：§13 推出兑现率 = **1 − WC/溢价**，其中 WC 是"选中收益里
来自 `val` 划分自身噪声、而非真实进步"的那一部分（胜者诅咒项）。两条推论都能在归档上检验，且两条都成立：
① 不等号是**逐 run**的，不只是均值：两侧都测过的 **81** 个 run 上，WC = `prem_val` − `prem_test`
平均 **+0.463 pp**（t = 8.34，p = 1.8×10⁻¹²），**68/81** 个 run 的兑现溢价更小；
② 兑现率应随 **`val` 曲线变噪而下降**：按各自 val 曲线的噪声尺度 σ̂ 三分位排序，兑现率为
**65.6% / 49.8% / 13.8%**，Spearman **ρ = −0.466**（p = 1.3×10⁻⁵，n = 80）。
**因此本节的 19% 与 §8.7 的逐格差异是同一句话在不同噪声水平上的取值**——这正是我们不把 19% 写成惯例常数的原因。
**不成立**的是我们最早写下的更强形式——溢价本身按 σ√(2 ln E) 缩放：回归斜率 0.026 ± 0.222（p = 0.82，n = 101），
因为**溢价的水平由 `val` 曲线的形状决定**（峰值离末轮多远）。§13 记录了这次撤回。

   所以**"溢价存在"与"基准别名"是两条独立证据，不能互相代替**——本节只支持前者（§4 与 §6 支持后者）。
2. **确切下载版本不可证**：可证的是"**我们分析的字节 = 这些哈希**"，而不是"这些字节 = 当时 Kaggle 的那一版"
   （来源表记的是**探查当时**的 `currentVersionNumber`；`ikram0703` 为 2，其余为 1）。
3. **端点是上界读法**：公开仓库通常不记录"报告的是哪一轮"，本节假设报告的就是 best。
4. **许可**：**5 个来源未标注许可**（Kaggle 侧 `Unknown`），GitHub 来源的仓库内有 `LICENSE` 但本目录未留存其内容；
   我们**不再分发**这些 CSV，只分发哈希与来源指针；引用其派生统计量时应说明来源未标注许可。

**一条必须记录的缺陷（一次静默排除）**

首版脚本用子串 `'mAP50-95' in 列名` 去认指标列，**只认 Ultralytics 的新拼写**。

**由这一次失败得到的三条口径改进**（已沿用为本项目的通用做法）：
① 逐行**标出该日志用的是哪种列名拼写**（两种拼写指同一个量，但列名不同——任何"用列名去筛日志"的脚本都会漏掉另一支）；

其中 5 轮那条的"最优轮 − 末五轮均值"会给出 +12.94 pp 这种无意义值——**它正是"轮数过少"必须排除的示范**，
故本节只报 `max − final` 的 20 条。

> **不参与 §5.1 的分级结论**（那里的两级报告用的是我们自己的配对设计）。两套证据**不互证**。

### 5.6 Δgap 的符号为何按语料而异：候选人机制里三种被数据排除

§5.1 第二级只报了"符号按语料而异"这个**事实**，没有解释**为什么**。本节把能想到的机制逐一对数据检验——
**结论是：用归档里现有的量，这个机制不可识别；但可以排除三种、另有两种不成立，并给出一个精确分解说明符号为何不稳。**

**数据**：13 个三分划语料格 × 2 臂（配对种子 n = 3 或 10）。
脚本 `work\gap_mechanism_20260916.py`（纯本机、读本地归档、**无需 GPU**），输出 `gap_mechanism_20260916.txt`；
数据通路与 §5.4 的核对脚本**完全相同**，且本节逐格 Δgap 与 §5.1 第二级表**逐值一致**（可交叉核对）。

**一个必须先说清的恒等式**：Δgap =（val 上的臂间差）−（test 上的臂间差），因此
**Δgap > 0 ⟺ val 上的相对臂间差小于 test 上的**。
这只是"两臂相对差在两个划分上作比较"，**本身不指向任何生成原因**——所以下面要一个一个查。

**逐条检验**（判定与反例都由脚本给出，反例是硬性的：只要有一个反例，机制就被排除）

| 候选机制 | 预测 | 判定 | 反例 / 证据 |
|---|---|---|---|
| **M1 乘性增益** | 策略按固定**比例**改进 ⇒ Δgap 与 gap 同号 | **被排除** | 3 处：`mask20`（gap −31.2 而 Δgap +1.75）、`p_aitovis`（+1.03 而 −1.23）、`p_vistod15`（+5.34 而 −3.32） |
| **M2 天花板压缩** | val 越容易（\|gap\| 越大）越压缩策略优势 ⇒ Δgap 随 \|gap\| 增大而变负 | **被排除** | \|gap\| > 10 的 6 个格 Δgap **全部为正**（+0.35 ~ +13.66）；全体 r = +0.32，p = 0.28 |
| **M3 水平决定可分辨性** | mAP 量级高的格更易显著 | **不成立** | 4 个显著格 val 基线均值 **36.83 pp**，9 个不显著 **36.79 pp**（Welch p = 0.998） |
| **M4 策略在 test 上是否真有增益** | 只有 test 上有增益的格才可能 val 低估 | **被排除** | 2 处：`p_aitovis`、`p_vistod15` 在 test 上策略更好，Δgap 却**为负** |
| **M5 val 侧选点获益之差** | Δgap 与（premium_基线 − premium_策略）同号 | **不成立** | 13 格中仅 **8 格同号**；r = +0.06，p = 0.84 |

**一个精确分解**（恒等式，用来解释"为什么符号不稳"——**不是**机制）

因为 `M_val(ê) = V_final + premium_val`，Δgap 可展开成三个**都能从归档直接算出**的分量：

Δgap =（**末轮 val** 上的臂间差）+（**val 侧选点获益之差**）−（**test 侧臂间差**）

| 语料 | Δgap | 末轮 val 差 | Δprem | −test 差 | 主导 |
|---|---|---|---|---|---|
| **mask20** | **+1.75** | **+15.78** | **−13.10** | −0.93 | 两个大分量**几乎抵消** |
| fire | **+13.66** | +15.96 | +2.08 | −4.39 | 末轮 val 差 |
| p_vistod15 | **−3.315** | −7.072 | −0.213 | +3.971 | 末轮 val 差 |
| p_aitovis | **−1.226** | −1.583 | +0.090 | +0.267 | 末轮 val 差 |
| shwd2sf | **+0.78** | −0.33 | +0.60 | +0.51 | Δprem |
| smoke2sf | **+0.46** | −1.06 | +0.09 | +1.43 | −test 差 |
| dota | **+0.35** | +0.75 | +0.54 | −0.93 | −test 差 |

这一分解是**恒等式而非拟合**：13 格的"校验"列（三个分量之和）**都等于** Δgap。
三个分量的中位量级分别是 **1.07 / 0.54 / 0.93 pp——同量级**，
⇒ **任一分量的抖动都足以翻转 Δgap 的符号**，这与 §5.1 观察到的"符号不稳"一致。

**最值得看的一格是 `mask20`**：基线在**末轮 val** 上领先策略 **+15.78 pp**，
但策略的 **val 侧选点获益**比基线大 **13.10 pp**，两者几乎抵消，净 Δgap 只剩 **+1.75**（且 p = 0.66，不显著）。
**这一格说明"选点"本身可以吞掉 13 pp 量级的臂间差**——它同时支持"该惯例会改变臂间比较"（§5.1 第一级），
也说明**不能**用 Δgap 的符号去反推任何单一原因。

**因此本节的主张是**（**已在 GPU 上补做后升级**）：Δgap 的符号**按语料而异**这一点是稳的（§5.1 已报）；
而**它的生成机制现在已经可分解**。补做的是：对 41 个三分划 run 用 `last.pt` 再评一次 `test`，
从而得到 `prem_test = T_best − T_final`（此前缺失的那一半），于是

Δgap =（**末轮 checkpoint 上的两划分难度差**的臂间差）+（**选点乐观 val−test 之差**的臂间差）

两格（各 n = 10）的分解结果（→ §8.6）：

| 格 | Δgap | **Δ难度差** | **Δ选点乐观** | 主导 |
|---|---|---|---|---|
| shwd2sf | **+0.779** | **+0.759** | +0.020 | **难度差** |
| smoke2sf | **+0.461** | **+1.041** | −0.580 | **难度差** |

⇒ **在这两格里，Δgap 主要由"末轮 checkpoint 上两划分难度差"的臂间差决定，而不是由选点乐观决定**；
`smoke2sf` 里两个分量甚至方向相反（+1.041 vs −0.580）而部分抵消。
这一条**收窄**了"val 高估/低估是选点造成的"这一直觉读法：至少在这两格，**是端点本身的难度差，不是选点**。

**仍然开着的**：其余 11 格的 run 不在这台机器上，故它们的分解**未做**——
`p_aitovis`、`p_vistod15` 两个负号格（各 n = 3）因此**没有**分解。三种候选机制（M1/M2/M4）已被反例排除、
M3/M5 不成立，这两条结论不依赖补做；**分解只覆盖 2/13 格，不得当作全部 13 格的结论。**

COCO 的 test 标注不公开——Detectron2 把它写成 `image_info_test2017.json`（**只有图像信息**），

这一条**支持**本文的问题意识：这不是个别人的坏习惯，而是**默认路径本身**。

**（C-2，收窄）但"在该划分上选 checkpoint"不是这五个框架的普遍默认——只有 YOLO 系默认这么做。**
Ultralytics（`best.pt`）与 YOLOX（`best_ap`）默认按验证指标选点；
而 Detectron2（`EVAL_PERIOD = 0`）、MMDetection（无 `save_best`）、DETR（不跟踪 best）的**默认是报末轮**。
⇒ 因此 §5 的选择溢价主张应读作：**"在默认按验证指标选点的管线族（YOLO 系）里，该惯例使臂间比较系统性偏移"**，
而**不能**写成"整个检测领域的默认"。**本文 §5 与 §6 的证据全部来自 YOLO 系管线，摘要说的也是"YOLO 配置"与
"通用 YOLO 分发包"——§6.5 把这条边界正式写明，并在 §5.1 的正式主张后加了"适用范围"句。**

**这一节自身的四条限制**（同写，以免被读成普查）：
① 我们读的是**默认配置**，用户可改（例如 MMDet 用户常加 `save_best='coco/bbox_mAP'`）；
② 只有 **5 个框架 / 23 个文件**，这是**定点抽样不是普查**；
③ 固定的是**默认分支 head**，将来会变——故逐文件留了 sha256 与 commit，任何人可复核；
④ 与 §4、§6 一样，这是**配置层审计**，**没有下载任何数据集**。

## 7. 发现四：显著性口径

**证据**：`r10_pvalue_table_20260916_local.md`（读本地归档；另有 pod 版可逐格比对）。

### 7.1 n = 3 时置换检验**原理上不可能拒绝**

**n 个配对的符号翻转置换检验，最小可达双侧 p = 2/2ⁿ。** n = 3 → **0.25**。
表中所有 n = 3 的格，其"配对置换 p"都恰好等于 0.25——这不是"不显著"，而是**该检验在此 n 下没有分辨力**。
**经过 §5.1 的两处升格之后，头条两张表（Table 1、Table 2）里已经没有 n = 3 的格**；
仍为 n = 3 的是补充材料 Table S8 里那 9 个未过线的格。

**因此**：n = 3 的格只能写"**在配对 t 检验下显著**，非参数检验在此 n 下不可用"，
**不得**笼统写"p = 0.025"。审稿人只问一句"这是哪个检验"就能把口径问穿。

### 7.2 两种口径同时显著只在 n ≥ 6 出现

| 格 | n | Δ | paired t p | 配对置换 p（n = 10 下界 0.001953） | 逐种子为正 |

| smoke→SFCHD | **10** | **+1.434 pp** | 8.6×10⁻⁷ | **0.001953（＝下界）** | **10/10** |

### 8.6 ⭐ 选点获益的"兑现率"：**19%**

### 8.7 逐 epoch 版本：兑现率不是一个常数

§8.6 的 19% 只用了 **best / last 两个点**。三分划 run 的 `weights/` 里其实**保留了中间 checkpoint**
（`save_period=5`，每个 run 有 `epoch0,5,…,95` 共 20 个；全机 **3,854** 个 `epoch*.pt`），
于是可以对**中间 epoch** 也各评一次 test。第一版是隔四个取一个：**41 个 run × {0,20,40,60,80}** = **202 次评估、0 失败**（54 分钟）。共享评审规程（补充材料 S6）要求整条曲线而不是抽样，而这些 checkpoint 就在盘上，于是我们把**同 41 个 run 保留的全部 806 个 checkpoint 在不相交的 `test` 划分上评了一遍——0 失败**（4 片并行时每次约 17 秒）。其中**202 个 (run, epoch) 点与上一版四点抽样重合，逐点差 0.0000 pp**——同一批 checkpoint 被独立评了两次、同机同协议，这本身就是对端点规则的一次免费复现检验。

**先记一条指标上的自我更正**：第一版我用比值 `r(e) = ΔT(e)/ΔV(e)`，结果出现 **−860% 与 +1031%** 这类值——

本条只报两个不过分母的量：`ΔV(e) = V(e) − V(final)` 与 `ΔT(e) = T(e) − T(final)`，
汇总只给一个稳健的数——**ΔT 对 ΔV 的过原点回归斜率 κ**。

### 9.1 被登记的是什么

**H1（主假设）**：在**三个未饱和的新目标域**上（100 轮基线 mAP50-95 < 0.30），20% 预算微调时
把峰值学习率从 **0.001 提到 0.005**（其余全同；YOLOv12n + shapeiou），会带来**正向**的 mAP50-95 增益，
且该增益能被**十种子配对检验**分辨。
**判"复制成功"**（冻结原文）：**≥ 2/3 个域对**同时满足 {增益 ≥ **+0.30 pp**、配对 p < **0.01**、
10 个种子里 **≥ 8 个同向**}，且在三个域对上做 **BH（q = 0.05）** 后仍显著；**否则如实报告为未复制**。

**H2（调节变量）**：增益随目标域的 headroom 变化——在**已饱和**域上（100 轮基线 ≥ 0.30）同一策略的增益应 **≈ 0**。

**登记设计**（先于结果、非结果驱动）：三个 T1 对在三套航拍语料上构成一个**环**
（aitod → visdrone → dota15 → aitod），故"源域/目标域"的角色在每个对里都不同，避免单源或单目标混杂；
**70 run** = T1 三对 × 2 臂 × 10 种子（60）+ T2 饱和对照 2 臂 × 5 种子（10）；另有**改良追加的近似匹配对照 C**，后扩到十种子（**2 × 10 = 20 run**），故本实验**共 90 run**（70 登记 + 20 追加）。
另有 **outcome-blind** 的域位移量 D（s-OTDD，sliced 分支），**含对已发表 MAFA→mask = 7.1894 的精确复现校验**。

### 9.2 结果：**未达冻结判据**（第 3 行是通过的那一格）

**十个种子是怎么实现的**（要写明，因为 run 元数据会误导）：种子是通过**训练文件顺序的 shuffle** 装进去的，
**不是**框架的 `seed` 参数，因此每个 run 的 `args.yaml` 都记着框架默认值 **`seed: 42`**——这是预期的，
**不代表种子相同**。已核验：各格的逐种子 `results.csv` **互不相同**（每个注册对 20/20、饱和对照 10/10、
追加对照 20/20），同一 shuffle 种子可复现该 run，**§5.1 升格的两格用的是同一约定、也做了同一项核验**。
机制、框架版本与 `args.yaml` 明细见**补充材料 S12**（脚本 `work/check_seed_convention_20260918.py`）。

| 登记对 | n | Δ (pp) | 95% CI | paired t | 配对置换 p | 同向 | Δ ≥ +0.30 | p < 0.01 | ≥ 8/10 同向 | **单元判据** |
|---|---|---|---|---|---|---|---|---|---|---|
| T1-a dota15→aitod | 10 | **+0.147** | [−0.036, +0.330] | 1.816（p = 0.1027） | 0.123 | 6+/4− | ✗ | ✗ | ✗ | **FAIL** |
| T1-b aitod→visdrone | 10 | **+0.168** | [+0.083, +0.253] | 4.455（p = 0.0016） | **0.001953** | **10+/0−** | **✗** | ✓ | ✓ | **FAIL** |
| T1-c visdrone→dota15 | 10 | **+3.727** | [+3.534, +3.920] | 43.774（p = 8.5×10⁻¹²） | **0.001953** | **10+/0−** | ✓ | ✓ | ✓ | **PASS** |

**BH（q = 0.05，m = 3）后仍显著：1/3**（T1-c 2.5×10⁻¹¹、T1-b 0.0024、T1-a 0.1027 不显著）。
**→ H1 判定：未复制**（通过单元判据 1/3，BH 后仍显著 1/3）。

**⚠️ 措辞口径（本节的写法是有意选的）**：我们写"**未达冻结判据**"，**不写"假设被否证"**。
理由是一条独立的细节：**T1-b 是 10/10 全同向、置换 p 已达 n = 10 的可达下界，但幅度 +0.168 卡在 +0.30 之下**——
**方向稳定、幅度不足**。写成"否证"会把这条张力扔掉，而它本身就是结论。

**H2（饱和对照）未落入冻结文件的任何字面情形**（按登记原文，此类情形须记人工裁定，故本文标注为偏离）：

| 冻结判据的问法 | 实测 |
|---|---|
| \|Δ\| < 0.15 pp？（饱和域应 ≈ 0） | **否**（T2 mask→mendeley **−1.490 pp**） |
| p > 0.1？（应不显著） | **否**（paired t = −4.164，**p = 0.0141**，0+/5−） |
| 出现 ≥ +0.30 pp 且 p < 0.01 的**正**增益？（若出现则叙事崩） | **否** |

即：**既非"≈ 0 且不显著"，也未出现"正增益"，而是显著为负。** 按冻结文件的定义这不构成"叙事崩"
（崩的定义是饱和域出现正增益），但**它比"≈ 0"更强**：在饱和域上把学习率提高 5× 不只是无效，**方向是负的**。

### 9.3 近似匹配对照 C：增益**不依赖**标签空间改变

三个 T1 对**都改变了类别集合**，因此它们检验的是"域 **+ 任务**"复制。为把"标签空间改变"从披露升级为**对照回答**，
冻结文件 §8 追加了一个**标签空间近匹配**的未饱和格（dota → dota15，类别集合仅多一个容器吊车类）：

| n | Δ (pp) | 95% CI | paired t | 配对置换 p | 同向 |
|---|---|---|---|---|---|
| 10 | **+0.727** | [+0.640, +0.814] | 18.854（p = **1.53×10⁻⁸**） | **0.001953**（= n = 10 下界） | **10+/0−** |

冻结文件 §8 的字面读法是"若 (C) 也出现 ≥ +0.30 pp 且 p < 0.01 的正增益 → 说明增益不依赖标签空间改变"——
**两条都满足，故得到该读法下的结论**。（三种子前身 n = 3 时 Δ = +0.707、p = 0.0157 **未达门槛**，
且 n = 3 的置换可达下界是 **0.25**，**在该 n 上原理上不可能拒绝**；补到十种子才成为判定。
该格同样使用 `val`/`test` 同目录的 yaml，且本表用的是项目报告口径（best 口径）——见下表与 §10 缺陷 2。）

**这些 Δ 里有多少是别名本身（val 侧）**：四个格（T1-a、T1-c、饱和对照、对照 C）的配置把 `val:`/`test:` 指向同一目录，故训练期看到的量**就是**上报量，每个 run 自己的日志直接量出选择溢价 `p = max_e mAP50-95(e) − mAP50-95(末轮)`；按种子配对得 `d̄ = mean[p_基线 − p_策略]`，`Δ ≈ Δ_reported + d̄`。逐格 d̄ 与其区间见**补充材料 S12**（脚本 `work/x10_alias_audit_20260918.py`）。同口径下：**T1-a +0.198**、**T1-c +3.941**、**对照 C +1.133**。**T1-b 依构造不适用**（其 yaml 两键分离）。**裁定无一改变，但有一个量级要改**，我们写出较小的那个数。

## 11. 建议（面向使用者）

1. **报告前先查三个键**：`val` 与 `test` 是否指向同一目录/同一文件列表。
2. **若必须用被报告的划分选点**：明确写成"报告的是**选择过的值**"，并**并列给出选择无关端点**
   （末轮 / 末若干轮平均）——本文 §5.1 表明这一步会**放大**而非缩小臂间差异。
3. **报告检验口径**：n < 6 时置换检验无分辨力；n = 3 的显著性只由配对 t 提供。
4. **声明单位**：任何"多少基准有问题"的数字，必须写明是 release / protocol / yolo_dist / reported 中的哪一个。
5. **工具层面**：把"`val` 与 `test` 是否同源"做成流水线的**硬校验**——本文 §4.3 表明该失败由工具产生，
   工具也能拦住它。
6. **必须选点时，选平台、不选单峰**：40 个配对 run 上（只在 `val` 选点、只在不相交划分读数），
   `val` 的 argmax 只捕获可实现收益的 **30%**，而**前五个 epoch 的均值捕获 70%** —— 代价是报告的数比
   `val` 峰低 **0.73 pp**，而这部分恰恰属于该划分而非模型。

## 13. 形式化：四个量分别能、与不能识别什么

§5–§9 测了四个量：选择溢价、配对差分 Δgap、转移斜率 κ、兑现率。本节把它们放进**同一个模型**，
并说明各自能识别什么、不能识别什么。**证明在补充材料 S11**；每条命题都挂到本文已经测过的数字上。

**设定**：训练是随机映射（种子 ω、配方 θ、checkpoint e）↦ 权重；评测是划分 S 上的固定泛函 M_S(W)。
记 V(e) = M_val(W(e))、T(e) = M_test(W(e))，ê = argmax_e V(e)，e_f 为末轮。

**命题 1（raw gap 不可识别）**：V(ê) − T(ê) = [V(e_f) − T(e_f)] + [(V(ê) − V(e_f)) − (T(ê) − T(e_f))]，
即 **G = δ + o**（δ = 划分难度项，o = 选点乐观）。对任意 δ′，(δ′, G − δ′) 同样吻合观测
⇒ **不存在**只用端点对的估计量能分离二者。**使 Δgap 有意义的是配对假设**：同种子、同一划分对时
E[δ_base − δ_strat] = 0；而**别名配置下该假设按构造失效**（两臂的 δ 是**同一划分上的两个最大值**）——
这正是 §9 不能写成"干净协议结论"的形式化内容。

**命题 2（精确三分量恒等式）**：按臂相减得 **Δgap = Δδ_f + Δprem_val − Δprem_test**
（末轮 val 臂间差 + val 侧选点获益之差 − 末轮 test 臂间差）。这是**恒等式而非拟合**，
在 13 格与两个升格格（n = 10）上逐值成立。

**命题 3（Δgap 的符号**不能反推机制**）**：由三条实测事实支撑——三分量同阶（中位 1.07 / 0.54 / 0.93 pp）
故**主导项按语料而异**；**两个符号都出现**（逐格表：表 2、补充材料 S6）；
每条候选机制都被**符号不符**排除（M1/M2/M4/M5，表 S9）。
**我们不主张的**是"符号很脆"：扰动分析显示把单个臂间差项乘 1.1 时**0%** 的格翻转（数值见**补充材料 S11**）⇒ 诚实的说法是"主导项随语料而变"，不是"符号是噪声"。

**命题 4（兑现率 = 1 − 胜者诅咒份额）**：设 V(e) = v(e) + ε_e、T(e) = v(e) + τ + η_e，则
**E[premium_test] = E[premium_val] − WC**，**WC := E[ε_ê − ε_{e_f}] ≥ 0**，
故兑现率 = **1 − WC/E[premium_val] ≤ 1**。**不等号**只需"ê 由 val 选出"（这正是被审计的约定，故方向稳健）；
**闭式**还需 test 噪声不参与选择（别名时不成立——这就是 §9.4 只把它当偏差量级的原因）。
两条推论都在归档上检验过：不等式**逐 run** 成立，兑现率随 val 噪声**单调下降**（逐 run 值、三分位与秩相关见**补充材料 S11**）——**§8.6 的 19% 与 §8.7 的逐格差异因此是同一句话在不同噪声水平上的取值**。
第三种形式（溢价本身按 σ√(2 ln E) 缩放）**我们检验后撤回**：回归与诊断见**补充材料 S11**。

**命题 5（BH 依赖被声明的族）**：step-up 的临界线是 i/m·q，故**加入更小的 p 会抬高其后的线**，
拒绝数在族上**不单调**。本文自己就是实例：把两格升到 n = 10 后，13 格的存活数由 **0 变 3**（§5.1）。
⇒ 声明计数单位与比较族不是行文偏好，而是"这个数有意义"的前提条件。

**推论（溢价大半是形状；峰是最不该站的地方）**：以命题 4 的记号，`premium_r = shape(E) + ν_r` 是**恒等式**，
其中 `shape(E)` 是均值曲线的峰到末轮的落差。在 E = 50/100/200 的 30 个 run 上，`shape` 占溢价的
**71% / 90% / 88%**，而 `sd(ν)` 在 E 上几乎不动（0.135 → 0.124）；溢价增长 ×2.19，而 σ√(2 ln E) 只预测 ×1.24
—— 所以**水平由曲线形状决定，而非其抖动**。两个后果：（i）**兑现率低是应有之义**：val 侧溢价大部分是该划分
自身的形状，不是可转移的收益；（ii）**val 的 argmax 是最不该带走的 checkpoint**，其**原因是候选而非结论**
（检验见补充材料 S11）。在 40 个配对 run 上（只在 val 选点、只在不相交划分读数），argmax 只捕获可实现收益的
**30%**，两个峰同轮的 run 仅 **17.5%**，而**取 val 前五个 epoch 的均值可捕获 70%**。推导与全部表格见
**补充材料 S11**。



### 13.1 五次"判据先写定"的 GPU 实验

上述命题是可检验的，因此我们在租用 GPU 上把它们跑了，**判据都在跑之前写定**。五个结果里有两个是负的，
其中一个设计还被推翻重做，下面照实写。



**表 13.1** 六次实验、各自**跑前写定**的判据，以及结果（负结果照实写）。

| # | 实验 | 跑前写定的判据 | 结果 |
|---|---|---|---|
| G1 | 别名划分 vs 不相交切割（dota15） | 别名侧溢价高于不相交侧 | **作废**——同一批 checkpoint 上两划分难度差 **14.7 pp**，该比较（−0.582 pp）混入了难度效应 |
| G1″ | 同一池子三层切割的难度 | 其中两层层差 ≤3 pp | **满足**——C2 与 C3 仅差 **−0.122 pp**（C1 与两者差 +3.5 pp，不可用） |
| G1′ | 在 C2 上选点、在 C3 上读出（层匹配） | WC = `prem_C2` − `prem_C3` > 0，p < 0.05 | **不满足**——WC = **−0.069 pp**（t = −0.23，p = 0.83，n = 10）：**测不到抬高** |
| G2 | 选点划分 30 vs 90 张（test 固定） | 兑现率随变大而升；WC 比值落在 [1.4, 2.1] | **方向满足**（21.3% → 14.3%），**量级不满足**（比值 1.19 对 √3） |
| G3 | 轮数预算 E = 100 vs 200 | 溢价随 E 上升、p < 0.05、形状受控 | **满足**——**+0.289 pp**（t = 4.96，p = 7.8×10⁻⁴），形状 0.788 → 0.813 |
| G4 | 新语料（`mende20_3way`）2 臂 × 10 种子 | 恒等式成立；WC > 0 | **满足**——**WC = +5.21 pp**，CI [+4.82, +5.66]，**20/20 个 run 为正** |

满足的四条与不满足的两条合起来只是一句话：**选择偏差随"选择噪声的绝对量"与"选择机会数"变化，
而不随"两个划分是否同一份文件"变化。** 逐 run 数值表见**补充材料 S31–S33**。
**读表须知。** 有两点不能只从表里的数字读出。其一，§4 的配置层事实仍然成立——被报告的数**就是**被选中的数；
不成立的是"别名在此之上还额外加了一份可测的量"这个更强的读法。其二，偏差确实随"选择看到了什么"变化：
选点划分的大小比较（同一池子里 30 vs 90 张，test 侧固定、嵌套以保证只变大小）使两臂同向地移动兑现率，
轮数预算比较则让峰值相对位置几乎不动，故两者都不是形状造成的假象。第三个语料的复现把 test 侧单独评测
（共 40 次），方向与 §8.6 的 81 个 run、§5.1 的 40 个 run 一致。

**合起来的一句话**：正结果表明选择偏差是**选择噪声绝对量**的函数；负结果表明它**不是**"两个划分是否
同一份文件"的函数。把键别名化，只会让被报告的数变成**被选中的数**（这是"印出来的是哪个数"的陈述），
而分离划分所暴露的选点乐观项并没有改变。命题 4 的 WC 因此应读作"选中收益里的胜者诅咒份额"，
它由噪声决定。来源：`work/g1p_verdict_20260919.py`、`work/g2_and_g1p_verdict_20260919.txt`、
`work/g1pp_g3_g4_verdicts_20260919.txt`、`work/theory_p4_test_20260919.py`。
